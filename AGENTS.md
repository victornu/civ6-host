# Product extraction rules

## Current user priority — 9 November 2026

Read and write JSON metadata with explicit UTF-8. On Windows, never use
`Path.read_text()` without `encoding="utf-8"` for these files: repeated default
Windows-1252 reads expanded the delivery board from kilobytes to gigabytes.
Check metadata size before loading it; investigate a delivery board above
1 MiB instead of repeatedly parsing or rewriting it. Keep the existing monitor's
8 MiB hard read bound. Store historical proofs by path/hash, preserve originals
when repairing encoding, and do not embed whole proof bodies in the board.

Complete the local gameplay API across the agreed engine, content and turn-mode
scope before working on throughput or evaluating training quality. Keep the
existing native evidence and measured bottlenecks. Choose the next delivery by
missing observations, choices, effects or lifecycle coverage, independently of
what the current learner consumes. This supersedes the earlier pilot-first
permission below. The client and learner remain separate, with public and
privileged data isolated.

## Current chat goal — 6 November 2026

The active goal permits a bounded learner pilot on a qualified local GS + BBG
7.5.1 scope before the complete host is finished. The final host/content/self-play
scope remains intact. Keep the API model-independent and preserve existing
native qualifications; do not repeat an unchanged successful opening or Save

The learner architecture stays unchanged during host integration, and no costly

## Host-only completion objective — 30 October 2026

The user has now explicitly approved the revised method and autonomous work:
stabilize shared API contracts, implement independent families in parallel with
disjoint ownership, and group validation according to what changed. Use retained
native replies for pure client/data transformations; execute the engine for
changed native calls and appropriate interaction/duration milestones. Do not
wait for every Base detail before investigating expansion Load compatibility.
The Mac is for future training only: no macOS GameCore port or backend work.

The user replaced the chat goal: finish the complete reusable host repository
before returning to model/training development. The host is the model-independent
game API. Feature selection, normalization, CNN/LSTM encoding, rewards and
actor/critic architecture belong to civ6-agent, not this repository. Never remove
an API capability merely because the current model does not need it.

Keep player-scoped and privileged/administrative APIs explicitly separated, with
their visibility, precision and provenance documented and enforced. A native
getter is not automatically a public player observation. Do not discard useful
native data globally when removing it from the public channel. Matching the human
information boundary does not require rebuilding every graphical widget or text.
An observation is identified by episode/generation/turn/revision, not turn alone.

Completion means the requested gameplay/content/turn-mode scope is qualified,
with a reusable Python client, lifecycle, documented API, reproducible installation,
examples without a learner and reviewed distributable sources. Publication itself
is not authorized. Preserve the existing partial qualifications; do not treat this
new objective as evidence of completion or restart already-delivered work.

Read README.md first. This repository is a staged extraction of the existing civ6-rl-lab, not a new implementation.

One coherent delivery at a time. Do not copy game binaries, decompiled bodies, official data/captures, secrets or raw private logs. Preserve historical source hashes in the lab and record compatibility transitions. Never call a scaffold a working release.

Before repeating an expansion command trial, walk the retained successful Base
interval for that whole action family and inventory its callbacks/services.
Port the shared missing query families as a group; do not discover every known
missing callback through another expensive Load. Distinguish ABI/profile changes
from shared algorithms and reuse both when their source contracts match. Retained
Base intervals predict dependencies; they do not prove expansion behavior.

For that inventory, follow the actual native calls through shared helpers,
including configuration getters. A fixture that replaces a helper does not
qualify the helper's engine ABI. List those seams and check their selected
profiles before the next native run; do not infer full family coverage merely
from the outer event functions carrying an engine keyword.

An observed argument value is not an ABI range. When the complete builder,
normalizer and consumer establish the full scalar domain, admit that domain
with its existing owner/type guards rather than limiting the adapter to the
sampled value. Preserve the original evidence and record a scoped supplement
for such an admission change. Never infer a wider domain from samples alone.

For expansion facade queries, the retained EXE callsite is the authority for
method slot, argument layout and consumed return width. A matching DLL hash,
complete method body or descriptive profile name proves neither the selected
method's meaning nor its ABI. Any slot change needs explicit caller/interface
evidence; compare the actual vtable target and wrapped return against the
retained Base/XP1 contract before admitting it. Tests must check this independent
source correspondence, not merely repeat a proposed mapping in their fixtures.
For a refused native callback, first reuse its recorded `native_stack` to locate
the actual producer and caller in the pinned image. An absent literal event ID
does not justify another run: registration may derive it at runtime.

The dependency inventory must also cover non-A0 host/auxiliary services and
producer instance state. Before a grouped native retry, exercise newly reused
dispatch branches on the actual composed owner and FIFO, with only native
memory/calls replaced by fixtures. Isolated codec tests do not reveal missing
owner fields. Preserve the previous inventory hash and add a scoped supplement
when a new family was omitted; do not rewrite an old receipt as if it covered it.

For a multi-turn expansion group, inspect the expansion-specific update and
expiry producers reached by that group as well as creation callbacks. A Base
interval cannot reveal expansion-only lifecycle events, and a creation-only
source profile is not the whole lifecycle. Review whether a source-qualified
presentation callback can be omitted under the owned empty-receiver contract
before porting graphics-only conversions; never infer that permission from its
name or from an ignored return alone.

A delivery awaiting an external test prerequisite may be explicitly parked while one other necessary implementation proceeds. A memory preflight refusal is not itself a reason to stop the whole project. Do not poll or rerun unchanged checks; retain containment and use measured resource evidence when reviewing admission policy.

The host owns the protocol; civ6-agent consumes it. Keep public player observations separate from privileged training information. Do not silently omit human actions, fake unknown services, or substitute turn modes. Batch validation at the delivery boundary, with targeted ABI probes only for changed uncertainty.

No automatic training campaign, full-game launch, external publication or upload. Existing user authorizations and restrictions in the originating task still apply.
